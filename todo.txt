    second one is leaving. Side effect: pathIsClear() (:381-417) only
    tests invincibility on squares listed in `allMarbles` (:408-413),
    so an invincible marble stops blocking as soon as it is the second
    marble of the split.

    table.component.ts:118-169).

    findLegalMoveForCard() (:679-681), goes straight to

  invincible (it has just entered on its start square and has not
  moved yet), and the first marble's path crosses or ends on that

  without invincible marbles: "7 jouable ⟺ au moins un pion peut le

  What "only one action" can be built from
    - Discard: the server flag `gameState.canDiscard`
      (computeCanDiscard(), game.ts:1215-1221), read by isDiscardMode
      (table.component.ts:195-197). When true, discarding is the only
      action.
    - Forced "solidaire" entry: forcedSolidaireEntry
      (game-state.service.ts:339-345). The only legal action is to
      enter a teammate's reserve marble with an Ace, King or Joker.
    - Otherwise nothing lists the legal actions of a turn.
      findLegalMoveForCard() (packages/shared/src/move-validator.ts:
      644-683) returns only the FIRST legal action of a card. Building
      blocks: handCardPlayable (game-state.service.ts:612-620),
      playableMarblePositions (:466-541), getLegalAction() with an
      explicit Jack target (move-validator.ts:207-210),
      getValidSevenStepsForMarble() and getLegalSplit7Action() for
      the 7.
    - Choices hidden inside one card: Jack = which pair is swapped (the
      same swap can be reached from either marble, since any marble can
      be the source, :183-215); 7 = full move or any split (step count
      and second marble); Ace / King / Joker = enter a reserve marble
      or advance a marble in play, depending on the marble picked.
    - Empty hand: the server passes on its own, the client sends
      nothing (game.ts:658-659).
    - The rules already force the player: a discard is refused while a
      legal move exists (game.ts:1076-1078). The option therefore never
      changes the result of a turn, it only removes taps.
  Turn start on the client
    - `newTurn` (game-state.service.ts:633, emitted at :777-787, later
      when a teammate has just finished). The table reacts at

    - A "New turn" banner covers the board for
      NEW_TURN_BANNER_DURATION_MS = 2500 (packages/shared/src/

  Not a shortcut
    - Do not implement this by sending `turnTimeout`: the server would
      play its first legal move but flag it as a timeout, which shows
      "Time's up, the computer played for you" (game.ts:896-911,
      game-state.service.ts:726).

Open questions (ask first)
  Q1. Do choices with an identical result count as ONE action?
      (assumed: yes.) Two cases: several reserve marbles can enter with
      the same card (all end on the start square), and two cards of the
      same value in hand allow the same move. A strict reading of the
      note ("une seule carte sur un seul pion") says no. Two cards of
      DIFFERENT values that reach the same square stay two actions:
      what is left in hand differs.
  Q2. Delay before the automatic move. (assumed: a short fixed delay
      once the "New turn" banner is gone, about 1 s, as a named
      constant, so that the player sees whose turn it is.) The
      alternative is no delay.
  Q3. Feedback when a move is played automatically. (assumed: none
      beyond the usual card and marble animations.)
  Q4. Label in the menu. (assumed: "Auto-play On" / "Auto-play Off",
      same pattern as "Card Help On/Off".)
  Q5. Where the choice is stored. (assumed: per device, in
      localStorage, like the other in-game options; not on the
      account.)

Definition used below (pending Q1)
  List every legal action of the turn as: card value, kind (enter,
  move, promote, capture, swap, discard), marble moved (all reserve
  marbles counted as one), destination, and for a 7 split the second
  marble with its destination, for a Jack the unordered pair of
  marbles. Play automatically when that list has exactly one entry.
